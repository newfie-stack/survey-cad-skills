# Review-assistance readiness

Crown Plan Agent 0.10.0 is a development preview for assisted plan checking.
“Finished” for this software scope means the advertised evidence-based checks
work on supported original inputs, preserve unresolved work, export actionable
findings and install reproducibly. It does not mean every regulatory question
can be answered from a PDF or that professional acceptance has been obtained.

| Review task | Implemented workflow | Evidence still needed for a job |
|---|---|---|
| Read the plan and ordinary text mistakes | Full-titleblock/visual procedure, native intake and selected finished-plan comparisons | Original readable plan; assisted selection/reading for unsupported text or graphics |
| Check which company should be printed | Actual plan/form/registry comparisons; confirmed instructions as separate job QA | Correct subject/role and reviewed current reference; conflicts cannot be guessed away |
| Check legal description and disposition identity | Source-bound selected fields across plan and records | Actual accompanying form/job reference; legal extent is a separate spatial question |
| Check printed area/length arithmetic | Fixed sums, amendment and gross/net balances, category/record comparisons | Complete reviewed component scope, original units and explicit tolerance; categories/overlap remain separate |
| Check hybrid coordinate table | Physical native row order, formatting/categories, distinct OC count and inclusive 10 km diagnostics | Complete table, independently reviewed roles/provenance/common metric frame |
| Compare supplied digital evidence | Actual CAD/GIS point-export snapshot and exact-value comparison | Correct complete point set and matching reviewed frame; native DWG/SHP/schema/topology are separate |
| Make corrections easier | Source-bound comments and complete actionable index in a private review copy | Actual original plan and executable reviewed runtime; ambiguous locations stay unlocated |
| Recheck a revision | Existing same-basis original-PDF comparison | Both original revisions and consistent review context; no automatic comment closure |
| Review regulatory questions | All 144 dated manual paths and seventeen bounded executed paths across fourteen clauses | Current application-specific authority, unimplemented obligations, required records and qualified interpretation |

The agent must say what actually ran, what failed, what was blocked and what was
not requested. Mechanical PASS is a bounded comparison, not a whole-plan approval.
An absence of extracted text cannot establish a missing graphic or note when
visual-to-text completeness or alternative wording is unresolved.

## What further software tests can establish

Known regressions exercise actual invented PDFs/records and exact expected
outcomes, including clean controls and evidence blockers. Fresh forward trials
freeze code and inputs, conceal the oracle during review, preserve literal
outputs before grading, and distinguish model-assisted observations from
executed predicates. Source hashes and publication/installed-package receipts
identify the tested version. None of these train the model automatically or
estimate accuracy on all unseen real plans.

An authorized real source may be exercised only for the questions supported by
its actual evidence. Reusing a plan as its own application/registry or inventing
an approved baseline would invalidate validation. Retain missing references and
provisional control/geometry as blockers, with private source data outside GitHub.

## External acceptance still open

- Representative real jobs with their actual applications, active plan records,
  title/interest evidence and accepted CAD/GIS/control where required.
- Qualified survey/regulatory expected results and acceptance of the complete
  applicability/coverage, field geometry and resulting corrections.
- Production/distribution acceptance, including the appropriate external-
  dependency licensing basis and host capability verification.

These are evidence and professional decisions. They cannot be completed by
renaming a development preview, increasing a test count or publishing a skill.
